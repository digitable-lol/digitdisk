# `core/` — решающий слой digitdisk

Здесь живёт то, что digitdisk **решает**: к какому разряду отнести находку, что
про неё посоветовать и сколько она весит. Фактов отсюда никто не собирает —
файловую систему щупает хозяин в [`../host`](../host), а сюда подаёт значения.

## Что здесь исходник, а что вывод компилятора

| Путь | Что это | Правится руками? |
|---|---|---|
| `disk-inventory.flang` | **исходник.** Правила, пороги, примеры, постусловия | **да, только он** |
| `differential.flang` | **исходник.** Сверка двух печатей между собой | да |
| `out-go/` | вывод компилятора: тот же модуль, напечатанный в Go | **НЕТ** |
| `out-c/` | вывод компилятора: тот же модуль, напечатанный в C | **НЕТ** |

### `out-go/` и `out-c/` — это НЕ исходники

Это то, что напечатал компилятор flang из `disk-inventory.flang`:

```bash
flang emit --target go disk-inventory.flang --out out-go
flang emit --target c  disk-inventory.flang --out out-c
```

**Зачем они закоммичены, если это вывод.** Чтобы сборка из чистого клона
требовала только Go: кто клонировал digitdisk и хочет собрать двоичный файл, не
обязан ставить компилятор flang — решающий слой уже напечатан и лежит в дереве.

**Цена этого решения.** Вывод обязан оставаться в согласии с исходником.
Поэтому правка руками внутри `out-go/` или `out-c/` — **дефект, а не правка:**
`make -C core` начинается с `rm -rf out-go out-c` и сотрёт её молча. Меняется
поведение ядра — меняется `disk-inventory.flang`, потом печать, потом оба
изменения идут одним коммитом.

**Почему имена файлов там `opis_diska.*`, а исходник `disk-inventory.flang`.**
Имя выходного файла даёт **имя модуля** внутри исходника (`модуль «Опись
диска»`), а не имя файла. Так печатает компилятор; переименовать вывод значило
бы править его руками.

## Порядок работы

```bash
make -C core            # всё сразу: проверка, печать, сверка
make -C core проверка   # flang check + flang test: типы, завершаемость, 115 примеров
make -C core печать     # перепечатать out-go и out-c целиком
make -C core сверка     # 240 входов через оба напечатанных кода; расхождений должно быть 0
```

Компилятор flang — один двоичный файл, которому нужен только `cc`:
`brew install flang`, `asdf`, либо `make -C bootstrap` в клоне языка. Node он не
требует, и в этом дереве нет ни JavaScript, ни Python.

## Почему ядро не ходит в файловую систему само

В языке 22 поручения ввода-вывода, и обход каталога среди них есть. Ядро всё
равно остаётся чистым — по причинам, которые замерены, а не предположены; они
выписаны в шапке `disk-inventory.flang`. Коротко: отклик «Перечислено» несёт
только имена, без размеров; добыть размеры можно лишь запуском процесса
(8,82 мс на запуск — 16,5 минуты на дерево из 111 986 записей против 3,39 с);
а программа с объявлением `план` печатается лишь одной целью из восьми, то есть
самостоятельным двоичным файлом такой digitdisk уже не станет.
