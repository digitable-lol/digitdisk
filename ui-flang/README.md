# `ui-flang/` — раскладка экрана на flang

Здесь живёт то, чем digitdisk **раскладывает экран**: сколько клеток закрасить в
полосе, где обрезать строку, чтобы она не перенеслась и не утащила разметку,
какие строки раздела показать при этой прокрутке, какой знак у замера на
графике, какой номер у цвета в палитре терминала.

Ни одного факта отсюда никто не собирает и ни одного приговора не выносит:
решает [`../core`](../core), собирает [`../host`](../host), а сюда приезжают
числа и строки — и уезжают строки.

## Что здесь исходник, а что вывод компилятора

| Путь | Что это | Правится руками? |
|---|---|---|
| `flang-tui/` | **подмодуль.** Клон [flang-tui](https://github.com/digitable-lol/flang-tui) на закреплённом отпечатке | **нет, он чужой** |
| `out-go/` | вывод компилятора: шесть модулей библиотеки, напечатанных в Go | **НЕТ** |
| `Makefile` | как проверить, напечатать и сверить печать | да |

### Библиотека подключена, а не скопирована

`flang-tui` — **подмодуль**, а не копия. Это выбор, и вот его цена и польза.

Скопировать шесть `.flang`-файлов в дерево было бы проще: ни `git submodule
update --init`, ни второго репозитория. Но тогда на вопрос «откуда взялась эта
строка и как её перепечатать» отвечал бы только тот, кто копировал. Подмодуль
отвечает командой:

```bash
git submodule status ui-flang/flang-tui   # адрес и ТОЧНЫЙ отпечаток
git -C ui-flang/flang-tui log             # чей коммит принёс каждую строку
```

Библиотека при этом живёт своей жизнью: её примеры и её доказательства
завершения прогоняются у неё, а не переезжают сюда вместе с кодом. **Сверщика
с эталоном у неё больше нет**, и это не потеря, а итог: `flang-tui/tools/sverka/`
был последним рукописным Go в её дереве, работу свою сделал (две сверки —
494 467 входов против digitdisk 0.5.0 и 1 944 268 против 0.8.0, расхождений 0)
и убран вместе с `Makefile`. То, что он стерёг, теперь лежит **примерами внутри
самих модулей** — их 590, и они гоняются на каждый толчок:

```bash
FLANG=<путь> make -C ui-flang проверка   # те же 590 примеров, здешним прогоном
```

### `out-go/` — это НЕ исходник

Это то, что напечатал компилятор flang из исходников подмодуля:

```bash
flang emit flang-tui/flang/screen.flang --target go --out out-go/screen
```

**Зачем закоммичено, если это вывод.** Довод тот же, что у
[`core/out-go`](../core/README.md), и он тоже назван по признаку сборки, а не
вообще: 18 053 строки в git покупают признак `flangui` и — что важнее —
`tools/sverka-ui.sh`, единственный прогон, доказывающий, что две реализации
раскладки рисуют один экран. Он собирает дерево дважды и в своей же шапке
говорит: «Компилятор flang НЕ нужен — печать лежит в дереве». Уберите печать —
и этот прогон начинается со сборки семени: 1 мин 54 с при `-j4`, 1,7 ГиБ
памяти. Обычный `go build ./...` не читает отсюда ничего.

**Цена.** Правка руками внутри `out-go/` — **дефект, а не правка:** `make -C
ui-flang печать` начинается с `rm -rf out-go` и сотрёт её молча. Меняется
поведение раскладки — меняется библиотека в своём репозитории, потом здесь
переставляется отпечаток подмодуля, потом печать, и всё это идёт одним
коммитом.

**Единственная правка напечатанного, и её делает `sed`.** У всех целей печати
имя модуля Go одно — `flangprogram`, — а библиотек шесть, и в одной сборке они
столкнулись бы именами. Поэтому после печати имя переписывается на
`flang<имя>`. То же самое делает `./ярлык печать` у самой библиотеки — `make`
у неё больше нет, точка входа теперь `./ярлык`.

## Признак сборки `flangui`

Без признака раскладку считает рукописный Go
([`host/internal/ui/layout_stock.go`](../host/internal/ui/layout_stock.go)) —
это **умолчание, и оно не менялось**. С признаком её считает напечатанный flang
через мост [`host/internal/uiflang`](../host/internal/uiflang):

```bash
cd host && go build -tags flangcore,flangui -o ../digitdisk .
```

Вывод у двух сборок обязан совпадать байт в байт, и это не обещание, а прогон:

```bash
tools/sverka-ui.sh
```

## Порядок работы

```bash
make -C ui-flang проверка   # flang check + flang test по всем шести модулям
make -C ui-flang печать     # печать в Go, gofmt, go vet, go build
make -C ui-flang сверка     # перепечатать во временный каталог и сравнить с деревом
make -C ui-flang чисто      # убрать напечатанное
```

## Чего эта раскладка стоит

Постусловия печатаются в код и пересчитываются на каждом возврате. На
`AMD EPYC 7742`, кадр целиком плюс обрезка каждой строки по ширине окна
(`go test -run '^$' -bench Layout ./internal/ui/`):

| Что меряется | Go | flang | раз |
|---|---|---|---|
| кадр 80×24 | 0,170 мс | 21,3 мс | ×125 |
| кадр 200×50 | 0,226 мс | 29,4 мс | ×130 |
| **нажатие 80×24** | **0,126 мс** | **13,1 мс** | **×104** |
| **нажатие 200×50** | **0,192 мс** | **20,5 мс** | **×107** |

Кадр по таймеру рядом со сбором сведений (≈1,5 с) не виден вовсе — 2 % цикла.
Нажатие человек ждёт, и 13–21 мс — это предел, за которым начинается заметное:
пока укладывается, но без запаса, и на машине втрое медленнее уже нет.

Поэтому признак `flangui` **не умолчание**. Умолчание меняется тогда, когда в
собранном компиляторе появится ключ печати `--no-postconditions`: постусловия
доказаны обо ВСЕХ входах ядром, и пересчитывать их на каждом возврате в
работающем двоичном файле незачем.
